## The product boundary is yours

StateWeave keeps state in memory while an `Agent` instance lives. Durable storage, authorization, and reconnect belong to your application.

## Save after success

```ts
import { Agent, type AgentState } from "stateweave";

type SessionRow = { revision: number; state?: AgentState };
const current: SessionRow | undefined = await store.load(sessionId);
const agent = new Agent({ model, tools, state: current?.state });

const result = await agent.run(input, { signal: request.signal });
await store.compareAndSet(sessionId, current?.revision ?? 0, {
  revision: (current?.revision ?? 0) + 1,
  state: result.state
});

return result.finalAnswer;
```

A stateful `Agent` serializes calls inside one process, not across replicas. For multi-replica safety, use optimistic concurrency or one session worker.

<Accordion>
  <AccordionItem title="Learn about trusted, untrusted state">
    A browser may own `AgentState`, but the server must treat it as untrusted:
    1. enforce a byte limit before parsing;
    2. construct `Agent` to validate identities and causal order;
    3. authorize the session envelope;
    4. never let browser state choose server tools or credentials;
    5. return new state only after a successful run.
  </AccordionItem>

## Watch engine progress

`streamEvents()` reports causal progress and forwards provider tokens/metadata while each model action is being collected.

```ts
for await (const event of agent.streamEvents(input, { signal })) {
  if (event.type === "metadata") console.log(event.metadata.runId);
  if (event.type === "model_token") process.stdout.write(event.token);
  if (event.type === "model_metadata") console.log(event.metadata);
  if (event.type === "progress") {
    console.log(event.progress.phase, event.progress.detail);
    if (event.progress.graph) renderGraph(event.progress.graph);
  }
  if (event.type === "final") {
    await store.save(event.result.state);
    renderAnswer(event.result.finalAnswer);
  }
}
```

Phases: `context`, `model`, `tool`, `retrying`, `final`. Progress events may include the exact prompt, graph view, raw output, action, tool, or error. Model events are separate so a consumer can render provider tokens without mistaking partial protocol text for a final answer.

For just the answer:

```ts
for await (const answer of agent.stream(input)) {
  console.log(answer);
}
```

## Inspect without exposing everything

```ts
const state = agent.getState(); // lossless persistence
const graph = agent.getGraph(); // bounded-text visualization view
```

`getGraph()` maps causal nodes into consumer-safe nodes and edges. Large text is truncated; `AgentState` is unchanged.

```ts
import { graphToMermaid } from "stateweave";
console.log(graphToMermaid(agent.getGraph()));
```

Traces are more sensitive than the graph view. Each step can contain the exact prompt and raw output. Restrict access and retention.

## Handle aborted and failed runs

```ts
import { AgentRunError } from "stateweave";

try {
  await agent.run(input, { signal });
} catch (error) {
  if (error instanceof AgentRunError) {
    audit.write({ trace: error.trace, metrics: error.metrics });
    // agent.getState() still returns the last successful commit
  }
  throw error;
}
```

Closing a `streamEvents` consumer aborts its run. A failed run's graph explains what happened, but it is not the canonical session unless you model failures deliberately.

## Traces only when needed

```ts
const agent = new Agent({ model, tools, traceDir: ".stateweave/traces" });
```

`traceDir` writes successful run results as JSON. In hosted products, prefer an access-controlled event store with explicit retention.
