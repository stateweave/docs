## What it is

StateWeave makes an agent's **memory** a causal graph instead of a chat transcript.

Every fact, tool result, and answer becomes a small node. Nodes that build on each other are linked. Nothing is deleted. Each model prompt is a **bounded view** of that graph, not the whole graph.

```txt
immutable causal graph → bounded working view → one model action → graph
```

<Accordion>
  <AccordionItem title="Why a graph and not messages?">
    A list of messages only tells you what was said next. A graph also tells you:
    - which evidence supported an action;
    - which version of a file is current;
    - which fact replaced an older one;
    - what the model actually read.
    Meaning lives in the connections, not in position or prose.
  </AccordionItem>
</Accordion>

The provider still gets a linear stream of tokens, because transformers need one. StateWeave treats that stream as a **temporary view**. The graph stays the truth.

<div className="sw-invariant">
  <b>The one principle</b>
  <p>The graph is truth. The prompt is a view.</p>
</div>

## Who owns what

<div className="sw-boundaries">
  <div className="sw-boundary"><strong>StateWeave owns</strong><p>Nodes, projection, action parsing, tool evidence, validation, traces.</p></div>
  <div className="sw-boundary"><strong>You own</strong><p>The model, tools, persistence, policy, user interface, deployment.</p></div>
  <div className="sw-boundary"><strong>Provider sees</strong><p>One bounded prompt and a system instruction per call.</p></div>
</div>

StateWeave is not a model, database, vector store, or hosted memory product. It is the state machine under an agent.

## What you should know

- One public class: `Agent`.
- Durable object: `AgentState`.
- Only 10 kinds of node (see [Nodes](/concepts/nodes)).
- No LangChain, no LangGraph, no graph database.
